# Архитектура для будущей переработки

## Поток данных

Hearthstone → текстовые Power.log / Decks.log → разбор событий → игровое состояние
→ модели представления → Python–QML bridge → окна Qt Quick.

Трекер работает нативно в Linux; Wine/Proton используется игрой. Основная база
механик — frFR. Вторичные локали enUS/zhCN/ruRU содержат имена и тексты и подгружаются
лениво. Не подменять основную базу русской: часть производных механик вычисляется
по французским текстам при загрузке.

## Что важно сохранить

- Роли QAbstractListModel и свойства bridge — контракт QML с состоянием игры.
- Смена языка обновляет вид, не должна перезапускать игру или менять её язык.
- Имена колод и игроков — данные пользователя, их не переводят.
- Источник созданной карты локализуется отдельно от её названия.
- Настройки языка сохраняются; неизвестная локаль имеет безопасный fallback.
- `Cairn · ...` / app_id `cairn` связывают окна с правилами KWin.
- `WindowTransparentForInput` подходит предпросмотру, но мешает интерактивной панели.
  Запрет клавиатурного фокуса оверлею и запрет мыши — разные вещи.
- Отправка партий и архивирование имеют отдельные настройки. Редизайн не меняет согласие.

## Будущие направления рефакторинга — не выполнены

- Разделить Launcher.qml на страницы/компоненты после согласования навигации.
- Выделить общую систему текстов и устранить разрозненные таблицы перевода.
- Сократить визуальную ответственность bridge без переноса парсинга в интерфейс.
- Сделать проверку компоновки частью воспроизводимых снимков.

Нужность и объём каждого изменения определяются конкретной задачей, а не общим
желанием переписать существующий код.
