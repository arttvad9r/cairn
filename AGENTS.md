# Работа с проектом Cairn

## Общие принципы

- Общаться с владельцем на русском.
- Понимать цель и существующее поведение до выбора решения. Не считать первое
  толкование неоднозначного запроса утверждённым требованием.
- До вопросов исследовать исходники, документацию, историю Git и доступные инструменты.
  Не спрашивать о технических деталях, которые можно решить самостоятельно.
- При существенной неоднозначности задать один конкретный вопрос с 2–4 вариантами,
  рекомендуемый первым. Не принимать зависимое продуктовое решение до ответа.
- Не подменять прежние архитектурные или продуктовые решения без выяснения причин.
- Если запрошен анализ, не приступать к реализации. При разрешённой реализации
  доводить работу до проверенного результата без повторных согласований обычных шагов.
- Проверять результат сценариями, тестами и запуском; явно сообщать непроверенное.

## Контекст и границы текущей подготовки

Сначала прочитать START_HERE.md и docs/redesign/{STATE,PLAN,DECISIONS,ARCHITECTURE}.md.
Владелец согласовал намерение полностью переработать интерфейс запуска/настроек и
игровые панели. Конкретные макеты, стиль, новые функции и изменение поведения не согласованы.
Подготовка репозитория не является разрешением автоматически реализовать весь план.

- Сохранять русский язык и остальные локали; тексты карт брать из ruRU HearthstoneJSON.
- Не менять движок разбора журналов ради визуальной переработки без отдельной необходимости.
- Сохранять лицензии и авторство upstream. Не считать ресурсы HDT свободными для копирования.
- Сохранить назначение приложения: нативный трекер журналов. Не добавлять инъекцию,
  чтение памяти, Electron, аккаунты и отправку данных ради редизайна.
- Планы/предложения отделять от принятых решений в docs/redesign/DECISIONS.md.

## Безопасный цикл разработки

- Работать в ветке задачи; main содержит проверенную базу. origin — личный форк,
  upstream — исходный проект. Не отправлять изменения в upstream без отдельной задачи.
- Использовать .venv и scripts/dev-run.sh. Не запускать install.sh для обычной разработки:
  он изменяет рабочую установку, конфигурацию Hearthstone и правила окон KDE.
- Не перезапускать игру, не вступать в матчи и не менять рабочую установку просто для тестов.
  Для визуальной проверки использовать записанные обезличенные партии и tools/screenshot.py.
- Имена окон оверлеев `Cairn · ...` и app_id `cairn` участвуют в правилах и скрипте KWin.
  Их изменение требует совместимой миграции, а не только правки текста.
- Оверлеи не должны забирать фокус у Hearthstone. Окно настроек должно оставаться
  доступным для клавиатуры. Не применять запрет фокуса ко всему приложению.
- В Git не включать .dev, .venv, data/cards, личные журналы и пользовательские снимки.
  Локальный контекст машины лежит в игнорируемом .dev/LOCAL_STATE.md, если файл есть.

## Проверки

- `./scripts/test.sh` запускает pytest вне пользовательских настроек и проверяет число пропусков.
- Для переводов проверять полноту колонок языков, подстановки, загрузку/сохранение языка,
  названия и тексты карт, размеры и переносы реального QML.
- Для UI проверять обе панели, состояния «игра закрыта / меню / партия / итог»,
  длинные русские строки, наведение на карты, клики, Alt+Tab, фокус, полноэкранный режим.
- Проводить проверки со скачанной базой карт: без неё большая часть тестов пропускается.
- Метрики производительности измерять, а не переносить из заявлений upstream.
